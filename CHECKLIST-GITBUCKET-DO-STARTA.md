# Проверка GitBucket до старта курса

Пара 5 считается техническим риском №1. Этот чек-лист нужно пройти **на тех же компьютерах**, где будут работать школьники.

## Цель проверки

Новый ученик должен суметь сделать первый `commit + push` по твоей инструкции примерно за 10–15 минут.

Если процесс требует большого количества ручной настройки, курс надо адаптировать заранее.

## Проверить до первой пары

- [ ] GitBucket открывается со школьного компьютера.
- [ ] Ученик может войти в свой аккаунт.
- [ ] Репозиторий можно создать/получить без помощи администратора.
- [ ] Понятно, как проект попадает в репозиторий.
- [ ] Можно сделать commit.
- [ ] Можно сделать push.
- [ ] После push изменения видны в GitBucket.
- [ ] Понятно, как посмотреть историю commit.
- [ ] Понятно, как вернуться к предыдущей рабочей версии.
- [ ] Не требуется SSH-настройка, которую школьники должны делать вручную на уроке.
- [ ] Не требуется вручную создавать токены/ключи во время пары.
- [ ] Все нужные программы уже установлены, если они вообще нужны.

## Красный флаг

Если для первого `commit + push` нужно:
- устанавливать Git;
- открывать терминал и вводить много команд;
- настраивать SSH;
- создавать access token;
- вручную прописывать remote;
- разбираться с правами доступа,

то для группы с нулевым опытом это слишком сложно для одной пары.

В таком случае до старта курса нужно либо:
1. подготовить окружение заранее;
2. сделать максимально простой графический/веб-процесс;
3. сократить цель пары 5 до одного успешного сохранения проекта в GitBucket.

## Перед самой парой 5 преподаватель обязан сам пройти путь

1. открыть проект;
2. сделать изменение;
3. commit;
4. push;
5. увидеть изменение на сервере;
6. специально допустить одну ошибку;
7. восстановиться.

Если ты сам без подсказки не можешь пройти этот путь на школьном компьютере — урок ещё не готов.
