# Чек-лист аккаунтов до старта курса

Пройти **до первой пары**, а не во время урока.

## GitBucket

- [ ] Сервер GitBucket существует и доступен. Если его ещё нет — кто-то должен его поднять до старта, это не делается на уроке.
- [ ] У каждого ученика есть аккаунт.
- [ ] Ученик знает логин.
- [ ] Ученик знает пароль.
- [ ] Проверена почта, если требуется подтверждение.
- [ ] Понятно, как восстановить пароль.
- [ ] Двухфакторная аутентификация не создаёт блокер на школьных компьютерах.
- [ ] GitBucket открывается из школьной сети.
- [ ] Группа может войти одновременно.
- [ ] У преподавателя есть список логинов учеников.
- [ ] Понятно, что делать, если ученик забыл пароль прямо на уроке.

## AI-сервис

Подробно — в `06-ВЫБОР-AI-СЕРВИСА.md`. Коротко:

- [ ] Выбран основной сервис.
- [ ] Прочитаны возрастные условия.
- [ ] Вопрос согласия родителей закрыт либо выбран вариант с работой через проектор.
- [ ] Сервис открывается из школьной сети.
- [ ] Не требуется банковская карта.
- [ ] Проверены лимиты при одновременной работе группы.
- [ ] Есть запасной сервис или подготовленные шаблоны.

## Школьный компьютер

- [ ] Ученик может создать папку.
- [ ] Ученик может сохранить файл с именем `index.html`, а не `index.html.txt`.
- [ ] Файлы не удаляются автоматически при выходе из системы. **Если удаляются — это меняет весь курс**, см. ниже.
- [ ] Есть браузер.
- [ ] Есть простой редактор текста или кода.
- [ ] Понятно, где ученик хранит проект между занятиями.

### Если профиль чистится между сеансами

Это частая ситуация в школах, и она ломает первые четыре пары. Варианты:

1. Договориться с админом об исключении для папки курса.
2. Ученики работают с флешки.
3. Ученики каждый раз в конце урока отправляют файл себе, а в начале — скачивают обратно. Медленно, но работает.
4. Перенести GitBucket на пару 3.

Реши это до старта, а не в момент, когда у класса пропала работа.

## За день до курса

Сам, сидя за школьным компьютером, пройди весь путь:

1. вход в AI-сервис;
2. создание папки и файла;
3. открытие страницы в браузере;
4. вход в GitBucket;
5. commit и push проекта в репозиторий;
6. возврат к предыдущей версии.

Если любой шаг неожиданно блокируется — исправляй до занятия. На уроке на это времени не будет.
