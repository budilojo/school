# Пара 5. GitBucket: только repository → commit → push

> Это одна из самых сложных пар для полного новичка. Сегодня не программируем и не добавляем новые функции. Успех пары — проект попал в GitBucket и ученик понял три действия.

## Что должно быть готово к концу пары

🟢 Минимум:
- проект есть в GitBucket;
- сделан **один commit**;
- сделан **один push**;
- ученик понимает, зачем это нужно.

🔵 Если группа успевает:
- сделать маленькое изменение;
- второй commit + push;
- посмотреть историю.

Не пытайся любой ценой сделать второй commit у всех.

## 1. Что говорить

Нарисуй на доске:

```text
МОЙ КОМПЬЮТЕР
      ↓
    commit
      ↓
     push
      ↓
   GITBUCKET
```

Скажи:

«Сегодня всего три новых слова.

**Repository / репозиторий** — место, где лежит наш проект в GitBucket.

**Commit** — сохранённая версия проекта с подписью “что я сделал”.

**Push** — отправить эти сохранения с компьютера в GitBucket.

Больше про Git сегодня знать не надо».

Не произноси без необходимости: branch, merge, rebase, conflict.

## 2. Что показать

Перед занятием сам полностью пройди процесс на демонстрационном проекте.

На уроке:

1. покажи свою локальную папку проекта;
2. покажи репозиторий в GitBucket;
3. покажи, как проект попадает туда вашим выбранным способом;
4. сделай commit `Первая рабочая версия`;
5. сделай push;
6. открой GitBucket и покажи, что версия появилась.

Если группа идёт нормально:
7. измени одну строку;
8. commit `Изменил заголовок`;
9. push;
10. покажи две версии.

## 3. Какое задание дать

Скажи:

«Сегодня не добавляем ничего красивого. Наша задача — сделать страховку проекта».

1. Откройте свой проект.
2. Откройте свой репозиторий в GitBucket.
3. Перенесите/свяжите проект тем способом, который я только что показал.
4. Сделайте commit:
   `Первая рабочая версия`
5. Сделайте push.
6. Покажите мне или соседу, что проект виден в GitBucket.

Если успели:
7. поменяйте одну маленькую фразу на сайте;
8. commit `Изменил текст ...`;
9. push;
10. откройте историю.

## 4. Если кто-то сделал слишком быстро

🔵 Сделать второй осмысленный commit.

🟣 Добавить короткий `README.md`:
- тема;
- вопрос;
- что уже сделано.

## 5. Если всё пошло не по плану

### Не работает GitBucket у половины класса
Не превращай урок в часовую техподдержку.
- зафиксируй проблему;
- сохрани локальные проекты;
- разберись после занятия;
- продолжи перенос в начале следующей пары.

### Не работает у 1–2 учеников
Посади рядом с тем, у кого получилось. Сначала сравни шаги.

### Ученик не понимает разницу между commit и push
Вернись к схеме:

`компьютер → commit → push → GitBucket`

Commit = сохранил версию.
Push = отправил её на сервер.

### Всё потерялось
Не делаем новые AI-изменения. Сначала находим последнюю рабочую копию.

## 6. Как завершить пару

Спроси класс:

«Перед большой AI-правкой что делаем сначала?»

Обучи их отвечать:

**«COMMIT!»**

С этого занятия это становится ритуалом.

Проверка 🟢:
- проект в GitBucket;
- минимум один commit;
- push выполнен;
- ученик своими словами объясняет commit и push.

Домашка необязательная.
